Lesson 5: Sarsa and Q-learning

Now the agent learns to act, not just to predict. Sarsa and Q-learning learn action values Q(s, a) with the TD idea from Lesson 4, and choose actions with ε-greedy from Lesson 3. They are the two most famous value-based RL algorithms. The lesson ends with what to do when the table of Q-values becomes too large.

After this lesson you can:
  • Read and fill a Q-table, and choose actions from it.
  • Apply the Sarsa and Q-learning update rules by hand.
  • Explain on-policy vs. off-policy learning, and why Sarsa and Q-learning behave differently near a cliff.
  • Explain the difference between tabular RL and approximate (deep) RL.
Contents

1. From predicting to controlling

In Lesson 4 the policy was fixed and we only learned V(s). Now we want the agent to find a good policy by itself, without knowing the environment's rules. The recipe has two parts that run together, step after step:

  1. Evaluate: learn Q(s, a), "how good is action a in state s", from experience, using a TD update.
  2. Improve: choose actions ε-greedily with respect to Q: usually the best-looking action, sometimes a random one to keep exploring.

As Q becomes more accurate, the greedy choices get better; better choices produce better experience; better experience makes Q more accurate. This loop is called generalized policy iteration.

Why Q and not V? With V you need to know where each action leads to compare them. With Q, the comparison is direct: just look up Q(s, a) for each action and pick the largest. No model of the world is needed.

2. The Q-table

In tabular RL, the agent stores one number for every pair of state and action, in a table:

State ↓ / Action →A₁ (Up)A₂ (Right)…Aₙ (Left)
S₁Q(S₁, A₁) = −3.2Q(S₁, A₂) = −1.0…Q(S₁, Aₙ) = −5.4
S₂Q(S₂, A₁) = 4.1Q(S₂, A₂) = 2.0…Q(S₂, Aₙ) = 0.3
……………
SₘQ(Sₘ, A₁)Q(Sₘ, A₂)…Q(Sₘ, Aₙ)

To act greedily in S₁, look along its row and pick the largest number (Right, −1.0). All values usually start at 0, and one cell is updated after every action.

3. Sarsa

Sarsa applies the TD(0) idea to Q-values. After taking action A in state S, the agent receives reward R, lands in S′, and chooses its next action A′ (with ε-greedy). Then it updates:

Q(S,A) ←
new value Q(S,A)
old estimate + α
step size × [ R + γ·Q(S′,A′) − Q(S,A) ]
TD target — the whole bracket is the TD error

The name comes from the five things the update uses: State, Action, Reward, next State, next Action: (S, A, R, S′, A′).

Sarsa
initialize Q(s, a) = 0 for all s, a
for each episode:
    S ← start state
    A ← ε-greedy action from Q in S
    while S is not terminal:
        take A, observe R and S′
        A′ ← ε-greedy action from Q in S′      # choose the next action FIRST
        Q(S,A) ← Q(S,A) + α·(R + γ·Q(S′,A′) − Q(S,A))
        S ← S′ ;  A ← A′                       # and really take A′ next

4. Q-learning

Q-learning changes one thing: in the target, instead of the action A′ the agent will actually take, it uses the best action in S′:

Q(S,A) ← Q(S,A) + α × [ R + γ · maxa Q(S′, a) − Q(S,A) ]
Q-learning
initialize Q(s, a) = 0 for all s, a
for each episode:
    S ← start state
    while S is not terminal:
        A ← ε-greedy action from Q in S
        take A, observe R and S′
        Q(S,A) ← Q(S,A) + α·(R + γ·max_a Q(S′,a) − Q(S,A))
        S ← S′
Worked example: the same experience, two updates (α = 0.5, γ = 1) Current estimate Q(S, Right) = −2. The agent moves Right, gets R = −1, and lands in S′ where:
Q(S′, Up) = −4, Q(S′, Right) = −3, Q(S′, Down) = −100, Q(S′, Left) = −5.
Because of exploration, the next action the agent picks is A′ = Up.

Sarsa uses the action actually picked: target = −1 + 1 × Q(S′, Up) = −1 − 4 = −5.
Q(S, Right) ← −2 + 0.5 × (−5 − (−2)) = −2 − 1.5 = −3.5

Q-learning uses the best action in S′ (Right, −3): target = −1 + (−3) = −4.
Q(S, Right) ← −2 + 0.5 × (−4 − (−2)) = −2 − 1 = −3

5. On-policy vs. off-policy

Sarsa is on-policyIt learns the value of the policy it is actually following, random exploration included. If the agent sometimes stumbles, Sarsa's values include the cost of stumbling.
Q-learning is off-policyIt learns the value of the best (greedy) policy, even while it behaves differently (exploring). Its values assume "from the next step on, I will act perfectly".

Usually both learn good policies. The difference shows clearly when exploration is dangerous, as in the cliff world below.

What you should see after a few hundred episodes:

  • Q-learning learns the shortest route, right along the edge of the cliff. That is the best route for a perfect agent. But this agent still explores 10% of the time, and one random step down means −100. So while learning, Q-learning often falls.
  • Sarsa learns a safer route further from the edge. Its values include the risk of its own random steps, so it keeps its distance. Its route is longer, but it falls much less.

7. When the table gets too big: approximate RL

A Q-table needs one row per state. That works for a grid of 32 squares. It does not work for:

  • Board games: the 9×9 game of Go has around 10³⁸ possible positions; chess has more than 10⁴⁰.
  • Images: a video-game screen of 84×84 grey pixels has more possible images than there are atoms in the universe.
  • Continuous states: a robot arm's angles and speeds are real numbers, so there are infinitely many states.

Two problems appear: the table cannot fit in memory, and most states are never visited even once, so their values would never be learned.

The solution is approximate RL (also called function approximation): replace the table with a model — often a neural network — that takes the state as input and outputs a Q-value for every action.

Diagram: tabular vs. approximate

The update idea stays the same: compute the TD target R + γ·max Q(S′, a), and adjust the network's weights so its output Q(S, A) moves toward that target. The big benefit is generalization: learning about one state also improves the estimates for similar states the agent has never seen. The famous Deep Q-Network (DQN), published by DeepMind in 2015, used exactly this idea to learn dozens of Atari video games directly from screen pixels.

Tabular RLApproximate RL
StoresOne value per (state, action)The parameters (weights) of a model
Good forSmall, discrete problemsHuge or continuous state spaces
Unseen statesNo informationEstimated from similar states
StabilitySimple, well understoodHarder; needs extra techniques to train stably

8. Summary

  • Control = learn Q(s, a) + act ε-greedily on Q; the two improve each other.
  • Sarsa target: R + γ·Q(S′, A′), using the next action actually taken. On-policy.
  • Q-learning target: R + γ·maxa Q(S′, a), using the best next action. Off-policy.
  • Near danger, Sarsa learns safer behaviour; Q-learning learns the optimal route but suffers more while exploring.
  • When there are too many states for a table, a model such as a neural network approximates Q (e.g. DQN).
