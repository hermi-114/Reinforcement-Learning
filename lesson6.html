Lesson 6: Policy-based Reinforcement Learning

Everything on Day 2 was value-based: learn how good actions are, then pick the best. Policy-based methods skip that middle step. They learn the policy itself, as a set of probabilities, and nudge those probabilities toward actions that earned more reward.

After this lesson you can:
  • Give three reasons to learn a policy directly instead of a value function.
  • Turn action preferences into probabilities with the softmax function.
  • Explain the idea of policy gradient ("climb the hill of expected reward").
  • Apply the REINFORCE update by hand, and explain why a baseline helps.
  • Describe actor–critic methods, which combine both families.
Contents

1. Why learn the policy directly?

A value-based agent picks actions with ε-greedy on Q. That works well for many problems, but has some limits:

ProblemWhat goes wrong with value-basedHow a learned policy helps
Continuous actions
e.g. a steering angle from −30° to +30°		"Pick the action with the largest Q" means searching through infinitely many actions at every step.The policy can directly output an action (for example the average and spread of a steering angle).
Randomness is the best strategy
e.g. rock–paper–scissors		Greedy choice is deterministic. Always playing "rock" is easy to beat. ε-greedy is random only in a fixed, crude way.A policy can learn exact probabilities, such as ⅓ each, which no opponent can exploit.
Abrupt changesA tiny change in Q-values can suddenly flip which action is greedy, so behaviour jumps around during learning.Probabilities change smoothly, a little at a time, which often makes learning more stable.
Analogy A value-based learner is like a student who first gives every possible answer a score, then picks the top-scored one. A policy-based learner is like an athlete building instinct: after a good result, the movements that led to it simply become a bit more likely next time, without anyone writing down a score for each movement.

2. A policy with knobs: preferences and softmax

To learn a policy, we need a policy that has adjustable numbers, called parameters and written θ (theta). The simplest version gives each action a a number θₐ called its preference. The softmax function turns preferences into probabilities:

π(a) = e^θₐ / ( e^θ₁ + e^θ₂ + … + e^θₙ )
  • e ≈ 2.718. Raising e to a power always gives a positive number, so every action keeps some chance of being picked. The agent never stops exploring completely.
  • Dividing by the sum makes all probabilities add up to exactly 1.
  • Only differences between preferences matter: adding the same number to every θ changes nothing.
Worked example Preferences θ = (1, 2, 0) for actions A, B, C.
e¹ = 2.72, e² = 7.39, e⁰ = 1. Sum = 11.11.
π(A) = 2.72 / 11.11 = 0.24, π(B) = 7.39 / 11.11 = 0.67, π(C) = 1 / 11.11 = 0.09.
B is the favourite, but A and C still get picked sometimes.
Interactive: softmax

With temperature, π(a) = e^(θₐ/τ) / Σ e^(θ/τ). Low τ: almost always the favourite (nearly greedy). High τ: almost uniform (very exploratory).

3. Policy gradient: climbing the hill

Define the objective J(θ) as the expected return when the agent follows the policy with parameters θ. Different θ give different policies, and so different expected returns. Imagine all possible θ values as a landscape, with J(θ) as the height. We want to reach the top.

Animation: gradient ascent

The gradient is the direction in which J increases fastest, like the steepest uphill direction on a mountain. Gradient ascent repeatedly takes a small step uphill:

θ ← θ + η × (estimate of the gradient of J)

Here η (eta) is the step size. The challenge: we cannot see the landscape. We only have the rewards from the actions we tried. The policy gradient theorem tells us how to estimate the uphill direction from experience alone, and the result is surprisingly intuitive:

The core idea After the agent takes action a and gets a return G: make a more likely if G was high, and less likely if G was low, by an amount proportional to how good or bad the result was.

4. REINFORCE

REINFORCE (Williams, 1992) is the classic policy-gradient algorithm. For the softmax policy on a single-state problem (like the bandit), its update for every action k after taking action a and receiving reward R is:

θₖ ← θₖ + η × (R − b) × ( 1[k = a] − π(k) )
  • 1[k = a] is 1 for the action that was taken and 0 for the others.
  • So for the taken action, (1 − π(a)) is positive: its preference moves in the direction of (R − b).
  • For the other actions, (0 − π(k)) is negative: they move the opposite way, a little.
  • b is a baseline, usually the average reward so far. (R − b) asks: "was this result better or worse than usual?"
Worked example (η = 0.5, b = 0) Three arms, θ = (0, 0, 0), so π = (⅓, ⅓, ⅓). The agent picks arm 3 and gets R = 1.
Arm 3: θ₃ ← 0 + 0.5 × 1 × (1 − ⅓) = +0.333
Arms 1 and 2: θ ← 0 + 0.5 × 1 × (0 − ⅓) = −0.167
New probabilities: e^0.333 = 1.40, e^−0.167 = 0.85. Sum = 1.40 + 0.85 + 0.85 = 3.09.
π = (0.27, 0.27, 0.45). One good result made arm 3 noticeably more likely.

Why the baseline matters

Suppose every arm pays about 4 to 5 points, always positive. Without a baseline, (R − 0) is always positive, so every chosen action gets pushed up, the good ones only slightly more than the bad ones. Learning still works on average, but it is noisy and slow. With the baseline b = average reward, an arm paying 4.2 when the average is 4.5 gets pushed down, and one paying 5 gets pushed up. The baseline does not change which direction is uphill on average, but it greatly reduces the noise (variance) of each step.

REINFORCE for full episodes

With many states, the policy takes the state as input: π(a | s, θ), often computed by a neural network. REINFORCE then works like Monte Carlo from Lesson 4: play a complete episode, compute the return Gₜ from each step, and push up the probability of each action in proportion to (Gₜ − b).

REINFORCE
initialize policy parameters θ
for each episode:
    play the episode with π(·|·, θ):  S₀, A₀, R₁, …, S_T
    for t = 0 … T−1:
        Gₜ ← return from step t           (Rₜ₊₁ + γRₜ₊₂ + …)
        θ ← θ + η · (Gₜ − b) · (direction that makes Aₜ more likely in Sₜ)

"Direction that makes Aₜ more likely" is the gradient of log π(Aₜ | Sₜ, θ). For the softmax with one state, it is exactly the (1[k = a] − π(k)) term above.

5. Actor–critic: the best of both

REINFORCE waits for the end of each episode and its returns are noisy, just like Monte Carlo. The fix is the same as in Lesson 4: use TD. An actor–critic method has two parts:

Diagram
  • The critic learns V(s) with TD (Lesson 4) and computes the TD error δ = R + γV(s′) − V(s) after every step.
  • The actor is the policy. It uses δ in place of (G − b): if δ > 0 the action turned out better than the critic expected, so it becomes more likely; if δ < 0, less likely.

Actor–critic methods can learn after every step, work on continuing tasks, and have lower variance than REINFORCE. Many modern algorithms (such as A2C, PPO and SAC) are actor–critic methods with a neural network for each part.

7. Summary

  • Policy-based RL learns the action probabilities π(a | s, θ) directly.
  • Softmax converts preferences θ into probabilities; temperature controls how random it is.
  • Policy gradient = gradient ascent on the expected return J(θ): make actions with good results more likely.
  • REINFORCE: θₖ ← θₖ + η(R − b)(1[k = a] − π(k)). A baseline b reduces noise without changing the direction on average.
  • Actor–critic combines a policy (actor) with a TD-learned value function (critic).
