Lesson 4: Monte Carlo and TD Learning

The bandit had one state. Real problems have many states, and the reward often arrives many steps after the decisions that caused it. This lesson shows the two basic ways to learn values from experience in that setting: Monte Carlo, which waits for the end, and Temporal Difference (TD), which learns after every step.

After this lesson you can:
  • Explain what "model-free prediction" means.
  • Update a value estimate with the Monte Carlo rule, using the real return.
  • Update a value estimate with the TD(0) rule, and compute the TD target and TD error.
  • Explain bootstrapping and compare MC and TD (when each can update, bias and variance).
Contents

1. The task: learn values from experience

In Lesson 2 we computed values in the grid world because we knew the rules of the world: where each move leads and what reward it gives. Usually an agent does not know these rules. It only has its own experience: the states it saw, the actions it took and the rewards it received.

Methods that learn directly from experience, without knowing the rules, are called model-free. (A "model" here means the rules: "if I do this, where do I end up and what reward do I get?")

In this lesson we solve the prediction problem: the agent's policy is fixed, and we want to estimate V(s), how good each state is under that policy. In Lesson 5 we use the same ideas for the control problem: finding a good policy.

2. A running example: the random walk

Diagram

Five states A to E sit in a row. Every episode starts in the middle, at C. At each step the agent moves left or right with equal chance (50% each). The episode ends when it walks off either end. Walking off the right end gives reward +1; every other step gives 0. We use no discounting (γ = 1).

Because the only reward is +1 at the right end, the value of a state equals the probability of finishing on the right from there. The true values are:

StateABCDE
True V(s)1/6 ≈ 0.172/6 ≈ 0.333/6 = 0.54/6 ≈ 0.675/6 ≈ 0.83

The agent does not know these numbers. Can it learn them just by watching episodes? Both methods below can, and you can watch them do it.

3. Monte Carlo: learn from complete episodes

Idea: play a whole episode. When it ends, you know the actual return G from every state you visited. Move each state's estimate toward the return that actually happened.

V(s) ← V(s) + α × ( G − V(s) )

This is the pattern from Lesson 3 again: the target is the real return G, and α (alpha, for example 0.1) is the step size. If we used α = 1/(number of visits), V(s) would simply be the average of all returns observed from s, which is where the name comes from: Monte Carlo methods estimate things by averaging random samples (the name comes from the casino in Monaco).

Worked example (α = 0.1, all estimates start at 0.5) Episode: C → D → E → off the right end. Rewards: 0, 0, +1. Return from every visited state: G = 0 + 0 + 1 = 1.
V(C) ← 0.5 + 0.1 × (1 − 0.5) = 0.55. The same happens for D and E: each becomes 0.55.
Next episode: C → B → A → off the left end. G = 0 for C, B and A.
V(C) ← 0.55 + 0.1 × (0 − 0.55) = 0.495. V(B) and V(A): 0.5 + 0.1 × (0 − 0.5) = 0.45.
Analogy: timing your commute To estimate how long your trip home takes, you note the total time each day after you arrive, and average them. You never update your estimate during the trip, only at the end. That is Monte Carlo.

Strengths: the target G is the real outcome, so the estimate is unbiased: on average it aims at exactly the right value.
Weaknesses: you must wait until the episode ends, so it cannot be used for tasks that never end; and the return G can vary a lot between episodes (high variance), so learning can be slow and noisy.

4. Temporal Difference: learn from every step

Idea: do not wait for the end. After a single step from s to s′ with reward R, you already have a better guess of the return: the reward you just got plus your current estimate of the next state.

V(s) ← V(s) + α × ( R + γ·V(s′) − V(s) )
  • TD target: R + γ·V(s′). It replaces the real return G that Monte Carlo had to wait for.
  • TD error (written δ, delta): δ = R + γ·V(s′) − V(s). Positive δ means "things turned out better than I expected", so V(s) goes up. Negative δ means worse, so V(s) goes down.

This is the method called TD(0). Using an estimate (V(s′)) to update another estimate (V(s)) is called bootstrapping, from the saying "pulling yourself up by your own bootstraps".

Worked example (α = 0.1, γ = 1, all estimates start at 0.5) Step C → D, reward 0: target = 0 + 1 × V(D) = 0.5. δ = 0.5 − 0.5 = 0. No change.
Step D → E, reward 0: target = 0 + 0.5 = 0.5. δ = 0. No change.
Step E → right end, reward +1: the end state has value 0, so target = 1 + 0 = 1. δ = 1 − 0.5 = 0.5.
V(E) ← 0.5 + 0.1 × 0.5 = 0.55. Only E changed in this episode. In later episodes, the good news about E spreads back to D, then to C, one step at a time.
Analogy: updating your arrival time on the way home You leave work expecting a 30-minute trip. At the car park you see it is raining, so you now expect 40 minutes. On the highway traffic moves fast, so you revise to 35. You update your prediction at each stage, using the newest information and your current guess of the remaining time. You do not have to arrive home first. That is TD learning.

Pseudocode

Monte Carlo prediction
for each episode:
    play the episode with policy π,
    recording S₀, R₁, S₁, R₂, …, S_T
    G ← 0
    for t = T−1 down to 0:
        G ← R_(t+1) + γ·G
        V(S_t) ← V(S_t) + α·(G − V(S_t))
TD(0) prediction
for each episode:
    S ← start state
    while S is not terminal:
        A ← action chosen by π in S
        take A, observe R and S′
        V(S) ← V(S) + α·(R + γ·V(S′) − V(S))
        S ← S′

Notice the Monte Carlo loop uses the recursive return from Lesson 2 (G ← R + γG) to compute every return in one backward pass.

8. From prediction to control

Knowing V(s) tells us how good states are under the current policy, but to choose actions without knowing the rules of the world, we need to know how good each action is: Q(s, a). Both Monte Carlo and TD can estimate Q(s, a) in the same way as V(s). Combined with ε-greedy action choice from Lesson 3, this gives algorithms that improve the policy as they learn. The TD versions of this are Sarsa and Q-learning, the subject of the next lesson.

9. Summary

  • Model-free methods learn values from experience, without knowing the environment's rules.
  • Monte Carlo waits until the episode ends, then moves V(s) toward the real return G.
  • TD(0) updates after each step, moving V(s) toward R + γV(s′). The difference is the TD error δ.
  • TD bootstraps (uses its own estimates), which gives lower variance and works for never-ending tasks, at the cost of some bias.
