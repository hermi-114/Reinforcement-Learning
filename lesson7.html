1. The multi-armed bandit problem

The name comes from casino slot machines, once nicknamed "one-armed bandits" because they take your money. Picture a row of k such machines. Each turn you pull one arm and receive some points. Each machine pays randomly, around its own average, and you do not know the averages.

RL elementIn the bandit game
GoalMaximize the total points after all turns
ActionWhich arm to pull (k choices)
RewardPoints received on that turn
StateOnly one: the machines never change, so pulling an arm does not change what comes next
Valueq*(a), the true average payout of arm a; the agent's estimate is Q(a)

Because there is only one state, there is no delayed reward and no credit assignment problem. What remains is the pure exploration vs. exploitation dilemma from Lesson 3. That is why bandits are the standard first problem for RL.

Regret: measuring how well you play If you had known the best arm from the start, you would have pulled it every time. Regret is the difference between that ideal total and what you actually expected to get. Exploration causes regret now (you pull worse arms to learn) but reduces regret later (you find the best arm). Good strategies keep total regret small.

2. Play it yourself

Game: you vs. RL agents

Five machines, 25 pulls. Each machine pays a random whole number around a hidden average. Click a machine to pull it. At the end, the averages are revealed and your score is compared with RL agents on the same machines.

Notice what you did. In the first pulls you probably tried every machine (exploration). Once one seemed good, you kept pulling it (exploitation), perhaps checking another now and then. RL algorithms make exactly this trade-off, but by a precise rule.

3. Solving the bandit with RL, step by step

  1. Initialize an estimate Q(a) and a counter N(a) = 0 for each arm. Usually Q(a) = 0, or a high value X for an optimistic start.
  2. Choose an arm with a strategy: ε-greedy, optimistic greedy, UCB or a softmax policy.
  3. Pull the arm and observe the reward R.
  4. Update: N(a) ← N(a) + 1; Q(a) ← Q(a) + (1/N(a)) × (R − Q(a)). (Or use a fixed step size α.)
  5. Repeat until the turns run out.

A table that stores one Q(a) per arm is the simplest example of tabular RL: a Q-table with a single row.

4. The optimistic strategy with X = 10

Your course slides use the optimistic initial values strategy with X = 10. "X" is the starting value given to every estimate Q(a) before any pull. Here the machines pay on average between 2 and 8 points, so 10 is higher than any machine can really deliver: every machine starts out looking excellent.

Worked example (sample-average updates) All five estimates start at Q = 10. The greedy agent picks (say) machine 1 and gets 4 points. Q(1) = 10 + (1/1)(4 − 10) = 4.
Machines 2–5 still show 10, so the greedy agent tries machine 2 next; it pays 7, so Q(2) = 7. Then machines 3, 4 and 5 in turn.
After five pulls, every machine has been tried once, with no random exploration at all. From then on the agent pulls whichever looks best, and its estimates keep improving.
With a fixed step size α = 0.1 instead, Q(1) = 10 + 0.1 × (4 − 10) = 9.4: the optimism fades slowly, so each machine is tried several times before the agent settles. That is more exploration, at a higher early cost.
Experiment: four strategies on the same five machines

True averages 2, 3.5, 5, 6.5 and 8 (in random order each run), noise ±2.5. 200 pulls per run, averaged over 1,000 runs.

What the results show:

  • Greedy from 0 is stuck at about 20%: every machine pays more than 0, so after the first pull that machine's estimate is positive while the others stay at 0. The agent never tries anything else, and picks the best machine only when its very first choice happened to be the best (1 in 5).
  • ε-greedy improves steadily, but 10% of its pulls are always random, so it learns slowly and keeps paying for exploration.
  • Optimistic greedy with X = 10 tries every machine in the first five pulls, then exploits. It finds a good machine fastest and usually collects the most points, which is why the slides use this strategy.
  • X = 10 with α = 0.1 explores longer, so it starts slower, but it ends up choosing the best machine most often.

5. Real applications of bandits

Online advertising and A/B tests
Each version of an advert or web page is an arm; a click is reward 1. A bandit sends more visitors to the better versions while still testing, instead of splitting traffic 50/50 for weeks as a classic A/B test does.
News and recommendations
Each article or product is an arm. The system learns which ones readers engage with. When information about the reader is used too, this is called a contextual bandit.
Clinical trials
Each treatment is an arm and a successful outcome is the reward. Adaptive designs move more patients to treatments that look better as the evidence grows.
Games and points
The slot-machine game from your slides: the goal is total points after all turns, and the reward is the points per turn.

6. A full RL application: traffic light control

Unlike a bandit, a traffic light's actions change the future: keeping a light green now affects how long the queues will be later. So it is a full RL problem with states, as in Lessons 4 and 5.

RL elementTraffic light
GoalReduce congestion
StateLength of the north–south queue, length of the east–west queue, which direction is green
ActionsKeep the current green, or switch (switching wastes one time step, like an amber phase)
RewardMinus the total number of waiting cars at each time step: fewer waiting cars → higher reward

In this simulation, cars arrive more often from the north–south road (40% chance each step) than from the east–west road (20%). One car per step can pass on green. The simple controller switches every 10 steps no matter what. The RL controller learns with Q-learning (Lesson 5) using a Q-table: about 240 states × 2 actions.

Interactive: train and watch
Train the controller first, or watch the fixed timer.

After training, the RL controller gives the busier north–south road longer green phases and switches when a queue builds up on the other road. Nobody programmed that rule: it emerged from maximizing the reward (fewer waiting cars). Real research systems use the same idea with richer states, such as camera images and many connected intersections, and neural networks in place of the table (approximate RL, Lesson 5).

One pattern to remember Almost every algorithm in this course updates an estimate with:
estimate ← estimate + step size × (target − estimate)
The methods differ only in what they use as the target: a reward (bandit), a full return (Monte Carlo), a reward plus a bootstrapped estimate (TD, Sarsa, Q-learning), or a reward compared to a baseline (REINFORCE).
