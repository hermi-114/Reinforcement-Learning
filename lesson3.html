Lesson 3: Exploration vs. Exploitation

At the start, an agent knows nothing about its actions. To learn, it must try them. But every try spent on a bad action is reward lost. This lesson is about that tension, the most famous dilemma in RL, and the simple strategies used to handle it.

After this lesson you can:
  • Explain exploration and exploitation, and why an agent needs both.
  • Estimate the value of an action by averaging rewards, and update the estimate step by step.
  • Describe the greedy, ε-greedy, decaying-ε, optimistic-initialization and UCB strategies.
  • Read a learning-curve chart and say which strategy works better and why.
Contents

1. The dilemma

You have moved to a new city. After a week you have found one restaurant you like: it is reliably about 7 out of 10. Tonight, do you go back there, or try one of the twenty places you have never visited?

Illustration
  • Exploitation means choosing the action that currently looks best. It maximizes reward right now, based on what you already know.
  • Exploration means choosing some other action to learn more about it. It may cost reward now, but it can discover something better, which pays off for all the future choices.
Why you cannot do only one Only exploiting: you may never find the restaurant that is 10/10, because you never try it.
Only exploring: you keep eating at random places, including the bad ones, and never benefit from what you learned.
A good agent explores a lot when it knows little, and exploits more as its knowledge improves.

2. A simple test problem: the slot machines

To study this dilemma cleanly, RL uses the multi-armed bandit problem (Lesson 7 covers it in depth). There is a row of slot machines, called arms. Each pull of an arm pays a random number of points. Each arm has its own true average payout, written q*(a), but the agent does not know these averages. The goal: collect as many points as possible over many pulls.

There is only one situation (one state), so the only question is which arm to pull. That makes the bandit the perfect laboratory for exploration vs. exploitation.

3. Estimating how good an action is

The agent keeps an estimate Q(a) of each arm's true average q*(a). The most natural estimate is the sample average: the average of all rewards received from that arm so far.

Q(a) = (sum of rewards from arm a) / (number of times arm a was pulled)
Worked example Arm 2 has been pulled 4 times and paid 5, 7, 4, 8 points. Q(arm 2) = (5 + 7 + 4 + 8) / 4 = 6.
The fifth pull pays 9. New Q = (5 + 7 + 4 + 8 + 9) / 5 = 6.6.

The incremental update (no need to store every reward)

Storing all rewards would use more and more memory. Instead, we can update the average with just the old estimate and the count n:

Q_new = Q_old + (1/n) × (R − Q_old)

Check with the example: Q_old = 6, R = 9, n = 5 → 6 + (1/5)(9 − 6) = 6 + 0.6 = 6.6. Same answer, no list needed.

The most important pattern in RL NewEstimate ← OldEstimate + StepSize × (Target − OldEstimate)
(Target − OldEstimate) is the error: how wrong the estimate was. We move the estimate a small step towards the target. You will see this exact pattern again in Monte Carlo, TD, Sarsa and Q-learning. Often the step size is a fixed number α (alpha), such as 0.1, which lets the estimate keep adapting if the arm's payouts change over time.

4. Strategies for balancing the two

4.1 Greedy

Always pick the arm with the highest estimate Q(a). Simple, but dangerous: if a good arm gives a low payout on its first pull, the greedy agent may never try it again and get stuck on a worse arm forever.

4.2 ε-greedy (epsilon-greedy)

Choose a small number ε, such as 0.1. On each step:

  1. With probability 1 − ε (for example 90%), exploit: pull the arm with the highest Q.
  2. With probability ε (for example 10%), explore: pull an arm chosen completely at random.

Because every arm keeps being tried now and then, every estimate eventually becomes accurate, and the agent will find the best arm. The cost: it keeps exploring even after it knows the answer, wasting about ε of its pulls.

Decaying ε fixes this: start with a large ε (explore a lot) and slowly reduce it (exploit more as knowledge grows).

4.3 Optimistic initialization

Instead of starting every estimate at 0, start them at a high value X that is better than any arm can really pay, for example X = 10 when payouts are around 2 to 6. Now even a purely greedy agent explores:

  • It pulls some arm. The real payout is lower than X, so that arm's estimate drops.
  • The other arms still look like 10, so the agent tries them next. Each one disappoints in turn.
  • After every arm has been tried enough, the estimates are realistic and the agent settles on the truly best arm.

The phrase "optimism in the face of uncertainty" describes this: treat what you have not tried as possibly great. It is simple and effective, but it only encourages exploration at the start.

4.4 Upper Confidence Bound (UCB)

UCB explores more cleverly. It adds a bonus to arms that have been tried only a few times, because their estimates are uncertain:

choose the arm with the largest Q(a) + c × √( ln t / N(a) )

Here t is the total number of pulls, N(a) is how often arm a was pulled, and c controls how much to explore. Rarely-tried arms get a big bonus; well-known arms get a small one. Exploration goes where it is most useful, instead of being random.

7. The algorithm in pseudocode

Initialize, for every arm a:
    Q(a) ← 0          # or X for an optimistic start
    N(a) ← 0          # how many times arm a was pulled

Repeat forever:
    with probability ε:   A ← a random arm          # explore
    otherwise:            A ← arm with largest Q(a)  # exploit
    R ← pull arm A and observe the reward
    N(A) ← N(A) + 1
    Q(A) ← Q(A) + (1 / N(A)) × (R − Q(A))           # move estimate toward R

8. Summary

  • Exploitation uses current knowledge to earn reward now; exploration gathers information to earn more later. Both are necessary.
  • Action values are estimated by averaging rewards; the incremental form is Q ← Q + step × (R − Q).
  • Greedy can get stuck. ε-greedy explores at random with probability ε. Optimistic initialization makes untried actions look good. UCB gives a bonus to uncertain actions.
