Lesson 2: Rewards, Return and Value

Lesson 1 said the agent wants "the most reward in the long run". This lesson makes that idea exact. You will learn the return, the discount factor, policies, and the two value functions V and Q, which every algorithm on Day 2 is built on.

After this lesson you can:
  • Compute the return of an episode, with and without discounting.
  • Explain what the discount factor γ does and how to choose it.
  • Tell a deterministic policy from a stochastic one.
  • Explain the state value V(s) and the action value Q(s, a), and read them off a grid.
  • Use the simple Bellman idea: value now = reward + discounted value next.
Contents

1. Rewards: telling the agent what you want

The reward is the only way we tell an RL agent what its goal is. According to the reward hypothesis, any goal can be expressed as maximizing the expected total reward. In practice this means the person designing the problem must choose rewards carefully.

TaskGood rewardWhy
Escape a maze−1 for every step until the exitThe faster the escape, the higher the total
Win at chess+1 win, −1 loss, 0 drawRewards the result we actually care about
Traffic lightsMinus the total waiting time of all carsLess waiting gives a higher (less negative) reward
Slot-machine gameThe points won on each pullThe goal is the total points over all pulls
Reward what you want, not how to do it Suppose you reward a chess agent for capturing pieces. It may learn to grab pieces greedily and lose the game. Agents optimize exactly the reward you give them, sometimes in surprising ways. A well-known example: an agent in a boat-racing game found it could score more points by circling forever to hit the same targets than by finishing the race. The reward should describe what to achieve, not how to achieve it.

2. The return: adding up rewards

The return, written Gₜ, is the total reward collected from time t onward. For an episode that ends at time T:

Gₜ = Rₜ₊₁ + Rₜ₊₂ + Rₜ₊₃ + … + R_T

The agent's goal is to choose actions that make the return as large as possible, on average.

Worked example In the grid game from Lesson 1, the robot takes the shortest route: five moves that cost −1, then one move onto the goal worth +10.
G₀ = (−1) + (−1) + (−1) + (−1) + (−1) + 10 = 5.
A longer route with nine moves gives G₀ = 8 × (−1) + 10 = 2. The shorter route has the higher return, so it is better.

Why discount?

Two problems appear if we just add rewards:

  • Continuing tasks never end, so the sum can grow to infinity, and every policy might look "infinitely good".
  • Sooner is usually better than later. 100 points today is better than 100 points in a year, because the future is uncertain.

The fix is a discount factor γ (gamma), a number between 0 and 1. A reward that arrives k steps in the future is multiplied by γᵏ:

Gₜ = Rₜ₊₁ + γ·Rₜ₊₂ + γ²·Rₜ₊₃ + γ³·Rₜ₊₄ + …
Interactive: how much is a future reward worth?

  • γ = 0: only the very next reward counts. The agent is "short-sighted".
  • γ close to 1 (for example 0.99): rewards far in the future still count a lot. The agent is "far-sighted".
  • When γ < 1 and the rewards are bounded, the sum stays finite even for tasks that never end. For example, with reward 1 every step forever, G = 1 + γ + γ² + … = 1 / (1 − γ). With γ = 0.9, that is 10.
Interactive: return calculator

A useful shortcut: the return is recursive

Look at the formula again. Everything after the first reward is just γ times the return from the next step:

Gₜ = Rₜ₊₁ + γ · Gₜ₊₁

This means you can compute returns backwards from the end of an episode, one step at a time.

Worked example (γ = 0.9, rewards −1, −1, −1, +10) G₃ = 10 (the last reward)
G₂ = −1 + 0.9 × 10 = 8
G₁ = −1 + 0.9 × 8 = 6.2
G₀ = −1 + 0.9 × 6.2 = 4.58
This simple idea, "now = reward + γ × later", is the heart of almost every RL algorithm.

3. Policies: deterministic and stochastic

A policy π describes how the agent behaves. There are two kinds:

Deterministic
Always the same action in a state: π(s) = a.
Example: "In square (3,0), always go Up."
Stochastic
A probability for each action: π(a | s).
Example: "Up with 70%, Right with 30%."

Stochastic policies are useful while learning (randomness helps the agent try new things) and in games where being predictable is bad, such as rock–paper–scissors.

4. Value functions: how good is a state?

The return of a single episode depends on luck: the environment or the policy may be random. To judge a state fairly, we use the average return over many episodes. This average is called the expected return, and it gives us value functions.

State value V(s) Vπ(s) = the expected return if the agent starts in state s and then follows policy π.
In words: "How good is it to be here, if I keep behaving like this?"
Action value Q(s, a) Qπ(s, a) = the expected return if the agent starts in state s, takes action a first, and then follows policy π.
In words: "How good is it to do this action here?"

Q is the most practical one: if you know Q(s, a) for every action, choosing is easy. Pick the action with the largest Q-value. This is the core of value-based RL.

5. The Bellman idea

How did the grid compute those values? With the same "now = reward + γ × later" idea as the recursive return. For a single move from s to s′ that gives reward r:

Q(s, a) = r + γ · V(s′)

And for the best policy, the value of a state is the value of its best action:

V*(s) = max over actions a of [ r + γ · V*(s′) ]

This is a simple form of the Bellman equation, named after Richard Bellman. It says the value of a state depends on the values of its neighbours. Each "update sweep" in the demo applies this equation once to every square. Repeating it makes the values settle to the correct answer.

Worked example (γ = 0.9) The square just below the goal: moving Up lands on the goal. Reward +10, and the episode ends, so V(goal) = 0.
Q(below goal, Up) = 10 + 0.9 × 0 = 10.
One square further away: moving toward that square gives reward −1 and lands where V = 10.
Q = −1 + 0.9 × 10 = 8. Next: −1 + 0.9 × 8 = 6.2, and so on. Values shrink with distance from the goal.
Analogy: a smell spreading Imagine the goal gives off a smell that gets weaker with distance. A hungry robot only needs to move toward the stronger smell. Value functions are that smell: once learned, the agent just climbs towards higher value.

The Markov property

All of this assumes the state contains everything needed to predict what happens next. The past does not matter once you know the present state. This is called the Markov property, and a problem with this property is called a Markov decision process (MDP). In the grid world, knowing your current square is enough; how you got there does not change what each move will do.

6. Summary

  • The return Gₜ is the (discounted) sum of future rewards: Gₜ = Rₜ₊₁ + γGₜ₊₁.
  • The discount γ ∈ [0, 1] sets how much the future counts and keeps sums finite.
  • A policy can be deterministic (one action) or stochastic (probabilities).
  • V(s) = expected return from a state; Q(s, a) = expected return from taking action a in state s. Both depend on the policy.
  • The Bellman idea: value now = reward + γ × value next. Knowing Q, the agent picks the action with the highest Q.
